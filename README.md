## v0.1.9 — Gemini 무료 API 기본 연결 (2026-10-17)

- **Google Gemini가 기본**입니다: `start_ai_windows.bat` 실행 → 제공자 Enter(기본 1) → 모델 Enter(`gemini-3.1-flash-lite`) → Google AI Studio API 키 숨김 입력.
- 엔드포인트: `https://generativelanguage.googleapis.com/v1beta/openai/` (Google 공식 OpenAI 호환 API). 기존 OpenAI는 제공자 2 선택 시 계속 이용 가능합니다.
- 별도 API 키가 없으면 기존 `start_windows.bat`으로 로컬 규칙 분석·사건 관리 이용 가능.
- **Gemini 무료 티어는 계정/지역/사용량 제한이 있고, 무료 티어 입력이 제품 개선에 사용될 수 있습니다.** 실제 민원자료는 외부 전송 금지. 고정 해시와 일치하는 합성 TXT만 전송.
- AI 연결시험과 최대 4건 합성 정확도 평가를 실제 사용자 PC에서 시험해야 합니다. 자세한 내용은 `AI_API_연결_가이드.md` 참조.

## Windows 실행 (Python 3.10 이상)

1. Python을 설치하고 `Add Python to PATH`를 켭니다.
2. ZIP을 압축 해제하고 `start_windows.bat`을 더블클릭합니다.
3. 자동으로 브라우저가 열리지 않으면 http://127.0.0.1:8765 를 입력합니다.
4. 제공된 `samples/sample_application.txt`를 업로드해 시연할 수 있습니다.
5. PDF/DOCX/XLSX 사용 전에 `install_parsers_windows.bat`을 한 번 실행합니다. 이 작업은 인터넷이 필요합니다. TXT/CSV는 추가 설치가 필요 없습니다.
6. 검토·수정 후 `건축개요 검토 확정` → 우측 상단 `.bcase 저장` → 다운로드된 파일을 보관합니다.
7. 재개하려면 `사건 열기`에서 해당 `.bcase` 파일을 선택합니다.

프로그램은 **이 PC의 127.0.0.1**에만 접속합니다. 브라우저를 닫아도 로컬 작업공간 `workspace/active.bcase`는 남습니다. 하지만 파일 이동/백업을 위해서는 꼭 **`.bcase 저장` 버튼으로 사건파일을 다운로드**해야 합니다. 브라우저 정책에 따라 기존 파일 덮어쓰기보다 새 다운로드가 발생할 수 있습니다.

### Phase 1.5 — AI 분석 + 규칙 결과 교차검증

1. 신청서는 **무조건 로컬 규칙 기반으로만 업로드·추출**합니다. 업로드만으로 외부 API를 호출하지 않습니다.
2. 연결된 모델이 있다면 `AI 분석 · 원문 근거 비교` 영역이 활성화됩니다.
3. **합성·비식별 시험자료**임을 확인하고 전송에 동의한 다음 `AI 비교 분석`을 누릅니다.
4. AI는 신청서에서 추출한 텍스트와 구조화된 행·셀 정보(최대 260개 줄)를 분석하여 **16개 공통 건축개요 필드**에 대한 별도 초안을 만듭니다. 원본 PDF/XLS 바이너리 자체는 API에 보내지 않습니다.
5. 화면에 `규칙 기반 / AI 제안 / 일치·불일치·AI만 제안 / 출처` 비교표가 표시됩니다.
6. **원문 근거가 검증된 제안만 선택**할 수 있습니다. `선택 항목 반영` 후 건축개요를 다시 확인하고 `건축개요 검토 확정`을 누르세요.
7. 비교 초안, 출처, 반영 이력은 단일 `.bcase` 파일 내부에 보존됩니다.

**일반 실행의 기본값은 AI 연결 꺼짐이며, AI 실행 스크립트에서는 Gemini가 기본 제공자입니다.** API 키가 없는 사용자는 기존 로컬 분석·수정·저장 기능을 그대로 사용할 수 있습니다.

#### AI 서비스 설정 예시 (Windows PowerShell)

```powershell
cd "압축을_푼_폴더"
$env:AI_MODE="on"
$env:AI_BASE_URL="https://공급자-호환-API/v1"
$env:AI_MODEL="해당 서비스가 지원하는 모델명"
$env:AI_API_KEY="개인_키_여기에_입력"
python server.py
```

OpenAI 호환 `chat/completions` JSON API가 있는 LLM을 사용할 수 있습니다. 자체 서버 등 로컬 연결 시에는 `AI_BASE_URL="http://127.0.0.1:11434/v1"`과 설치한 모델 이름을 지정할 수 있습니다(해당 로컬 서버가 호환 엔드포인트를 제공하는 경우). 비용·토큰·모델 접근권한은 별도 확인이 필요합니다.

**보안 제한:** 외부 AI 호출은 문서 앞부분에 `모의`, `합성자료`, `가상주소` 등 **합성자료임을 나타내는 표식**이 있을 때만 허용합니다. 전화번호·이메일·등록번호 패턴이 발견되면 전송을 차단하고, 건축주·설계자 관련 줄은 전송 대상에서 제외합니다. 이 필터는 완전한 익명화나 안전을 보장하지 않으므로, 실제 건축인허가 신청서와 개인정보·비공개 민원자료는 **AI 전송 대상에서 제외**해야 합니다. 내부 승인 모델을 통한 실업무 사용은 별도 보안검토 후 추진합니다.

**기술적 제한:** 현재 AI 모델에는 추출된 **텍스트·셀 배치·체크표시 분석 결과**를 보내며 PDF 페이지 이미지 자체를 전달하지 않습니다. 스캔 PDF OCR·비전 기반 문서 파싱 및 복잡한 표 이미지 해석은 추가 개발 대상입니다. 모델 2종 비교 및 정확도 향상 수치는 아직 검증하지 않았습니다. 자동 테스트에서는 외부 AI 호출 없이 모의 응답만 사용합니다.

## 구조

```
server.py               로컬 HTTP API / UI 서빙 (표준 라이브러리만)
case_store.py           SQLite .bcase 관리 / 원본 보존 / 이력
parser.py               파일 텍스트 추출 / 규칙 기반 분석
ai_review.py            선택적 AI 비교 초안 / 출처 검증 / 안전 게이트
pdf_vectors.py          PDF 첫 장 벡터 체크도형 판독
xls_markers.py          XLS 그림 개체 체크표시 앵커 판독
index.html              업무 화면
static/app.js           업무 화면 동작
static/styles.css       스타일
masters/fields.json     공통 건축개요 마스터 (사건파일과 분리)
samples/                전부 가상으로 작성한 테스트 신청서
workspace/              실행 시 생성 (Git 업로드 금지)
tests/                  자동 테스트
```

사건 내부 테이블: `metadata`, `case_data`, `documents`, `history`, `records`(향후 협의회차 등 저장용). `application_id=BCAS`, `schema_version=1`을 확인하여 다른 SQLite 파일과 구별합니다. 원본 파일 내용은 `documents.content` BLOB, 추출 초안은 `case_data.values_json`, 수정 흔적은 `sources_json` 및 `history`에 별도 보관합니다.

## 알려진 제한사항

1. **스캔 PDF** 및 HWP/HWPX는 아직 지원되지 않습니다. XLS는 BIFF8 형식에 한하여 지원합니다.
2. 규칙 기반 파서는 `대지면적: 450㎡`와 같이 명시적 `항목명: 값` 형식에 우선 대응합니다. 복잡한 표·셀 병합 및 비정형 문서는 파싱 정확도를 실사례로 검증해야 합니다.
3. 외부 AI 호환성은 모델·제공자별 테스트가 필요합니다. AI 연결 없이도 로컬 분석은 정상 동작합니다.
4. PDF 등의 문서 추출은 추가 모듈 설치가 필요합니다.
5. 로컬 단일사용자 도구입니다. 권한관리, 행정망 연동, 감사체계, 개인정보 처리 승인 기능은 구현되어 있지 않습니다.
6. 이력은 주요 작업 단위이고 **모든 입력값의 변경 전·후 비교 기록**은 아직 아닙니다.
7. 사건파일의 보안은 저장 PC의 접근통제에 의존합니다. 암호화되지 않은 `.bcase`에는 실제 업무자료를 넣지 않습니다.
8. 현 버전은 `.bcase 저장` 시 다운로드 방식입니다. 네이티브 파일 직접 덮어쓰기 방식이 아닙니다.

## Phase 1.2: 실제 서식 구조 대응 (2026-10-14)

- 건축허가 2건·건축신고 2건의 PDF/XLS 형식으로 로컬 시험(원본 파일은 저장소에 올리지 않음).
- PDF 및 XLS에서 **첫 장의 「Ⅰ. 전체 개요」를 우선 추출**하고 동별·층별의 증축면적이 전체 연면적을 덮어쓰지 않도록 방지.
- 기존 `.xls`(OLE2/BIFF8)의 읽기 전용 셀 분석 기능 추가(`xls_legacy.py`), 기타 XLS 형식은 지원하지 않을 수 있음.
- 체크박스 표시가 문서 데이터에서 구분되지 않으면 건축구분을 추정하지 않고 담당자 확인 대상으로 남김.
- 합성 회귀테스트 포함 전체 자동 테스트 18개 통과, 실무 양식 기준 **추출된 필드 수 12~13/16**(정확도 수치 아님).
- 원본 PDF/XLS에 개인정보 및 비공개 민원자료가 포함될 수 있으므로 **GitHub·외부 AI에 업로드하지 말 것**.


## Phase 1.3 · 건축구분·동별·층별 구조화 (2026-10-14)

- 건축구분은 `[√] 증축`, `☑ 신축` 등 **명확히 표시된 체크만** 자동 확정합니다. 체크표시가 PDF 그림이나 XLS 도형에만 있으면 추측하지 않고 담당자 직접 선택으로 남깁니다. 층별 행의 '증축' 문자열을 전체 신청 건축구분으로 올려쓰지 않습니다.
- `seumteo_details.py`: 세움터 Ⅱ. 동별 개요의 **기존 / 신청란**과 Ⅲ. 층별 개요의 층·구분·면적을 분리하는 초안 생성. 면적 합산, 적법 판정, 증축 전후 비교에 따른 자동 승인 판단은 수행하지 않습니다.
- DB 스키마 변경 없이 `records(category='application_details')`로 상세 초안·출처·담당자 수정 이력을 단일 `.bcase`에 저장합니다. `POST /api/detail-update`는 허용한 항목만 수정하며 담당자 검토 확정을 다시 필요 상태로 돌립니다.
- 화면에 동별/층별 상세 편집표와 원문 줄번호 바로가기가 표시됩니다. PDF 층별 용도는 줄바꿈이 심할 경우 빈칸으로 두고, 담당자 확인을 요청합니다.
- 검증: 기존·신규 단위/HTTP 테스트 총 **26개 통과**. 사용자 제공 실무양식 4건은 개발 PC에서만 HTTP 업로드 → 구조화 → 사건파일 복원을 검증했습니다. **실제 신청서, 개인식별정보, 원본·추출 내용은 GitHub에 등록하지 않았습니다.**

## Phase 1.4 — 선택표시·대지 지번·주건축물수 (2026-10-15)

- PDF 체크표시: 첫 장 건축구분에 그려진 **채움 벡터 도형**을 해당 선택지의 텍스트 위치와 대조합니다. 단 하나의 명확한 표시만 자동 선택합니다. OCR·외부 AI는 사용하지 않습니다.
- XLS 체크표시: 구형 BIFF8 파일의 OfficeArt 그림 개체 앵커가 첫 장 건축구분 체크칸 안에 있음을 확인한 경우만 판독합니다. 도형이 없거나 위치가 모호하면 미확정 상태로 남깁니다.
- 대지위치: PDF에서 분리된 `대지위치`와 `지번`의 실제 값을 결합합니다. 건축주 주소 및 `관련지번`은 사용하지 않고 두 원문 줄을 기록합니다.
- 건축물 동수: 전체 개요에 `주건축물수 N 동`이 명시된 경우에만 추출합니다. 공란은 **담당자 직접 확인** 대상입니다.
- 체크도형 기반 추출값은 별도 출처 `PDF 벡터 체크표시` 또는 `XLS 그림 체크표시`로 표시합니다. 담당자가 수정·확정할 수 있습니다.
- 테스트: 합성 자동테스트 39건 통과. 실무용 대표 서식 4건은 로컬에서만 HTTP 업로드·분석·`.bcase` 내보내기·복원을 검증했습니다. 16개 항목 중 자동 추출 개수는 허가 XLS 14, 허가 PDF 15, 신고 XLS 14, 신고 PDF 13입니다. **추출 개수는 정확도 수치가 아닙니다.**
- 제한: 다른 제작 프로그램의 벡터·이미지 체크, 스캔 PDF, 비표준 XLS 컨트롤, 실제 Windows 화면 클릭 테스트는 아직 별도 검증이 필요합니다.
- 보안: 실무 신청서 원본, 개인정보, 실제 사건 내용은 GitHub와 공개 배포 ZIP에 포함하지 않습니다.

## Phase 1.6 — 외부 전송 없는 모의 비교 검증

기존 v0.1.5 사용자 검증에서 TXT 신청서 추출, 수정·확정, 재확정, `.bcase` 저장·복원은 정상 확인됐습니다. 그 범위를 바탕으로 별도 AI API 계정 없이도 **비교표의 동작을 검증할 수 있는 모의 응답**을 추가했습니다.

- 모의 비교는 `samples/sample_application.txt`와 **바이트 단위로 동일한 파일**에서만 실행합니다. 파일 내용의 SHA-256이 다르면 서버가 거절하고 화면 버튼도 비활성화됩니다.
- 모의 비교 엔진(`demo_review.py`)은 합성 파일에서 규칙으로 정답값을 복원해 비교 초안을 만드는 **결정적 테스트 도구**로, LLM을 실행하지 않고 외부 네트워크를 전혀 호출하지 않습니다.
- 실제 AI 비교 버튼과 모의 비교 버튼은 별개입니다. 실제 AI는 기존과 같이 명시적 설정·동의·보안검증이 필요합니다.
- 모의 결과는 `모의 응답 · 실제 AI 아님`이라고 표시되며 출처에도 `모의 비교 제안 (실제 AI 아님)`이라고 기록됩니다. 결과는 AI 추출 성능의 측정치가 **아닙니다**.
- API `/api/demo-review`는 가장 최근 문서의 원본 해시를 검사하고 담당자가 선택하기 전에는 기존 입력값을 변경하지 않습니다.

### 사용자 검증: 모의 불일치·누락·선택 반영

1. `start_windows.bat`으로 v0.1.6을 실행하고 `samples/sample_application.txt`를 업로드합니다.
2. 대지면적을 `450.00` → `500.00`으로 **의도적으로 수정**하고, 주차대수 `2`는 **빈칸으로 지웁니다**. 아직 검토 확정은 하지 않아도 됩니다.
3. `모의 비교 체험 (외부 전송 없음)`을 누릅니다. 체크박스/AI API 키가 필요 없습니다.
4. 비교표에서 대지면적이 **불일치**(기존 500.00/제안 450.00), 주차대수가 **AI만 제안**(기존 공란/제안 2)으로 나오는지 확인합니다. **이 용어는 비교표의 공통 상태 라벨일 뿐 실제 AI 호출을 뜻하지 않습니다.**
5. 제안값을 선택하기 전 원래 입력값이 그대로인지 확인합니다. 두 항목을 체크하고 `선택 항목 반영`을 누른 후 대지면적 450.00, 주차대수 2가 입력되는지 확인합니다.
6. `건축개요 검토 확정` → `.bcase 저장` → `새 사건` → `사건 열기`를 진행합니다. 모의 초안·선택 반영 결과·근거·이력이 복원되는지 확인합니다.
7. 실제 서식 PDF/XLS에서는 모의 비교 버튼이 비활성화되는 것이 정상입니다.

**실제 모델 검증(추후):** 외부 AI 연결·모델 2종 비교·정확도 수치는 아직 수행하지 않았습니다. 실무 신청서의 개인정보를 외부 API로 전송하지 마세요.

## Phase 1.8 — 외부 AI API 연결 안전성 보강 (2026-10-17)

## Phase 2 · 건축법 검토 체크리스트 (v0.2.0, 2026-10-19)

검토항목 후보 템플릿은 `masters/legal_checklist.json`에 있습니다. **현행 법령 내용과 파주시 조례의 최신 기준을 담은 확정 법령 데이터베이스가 아닙니다.** 해당 조문은 국가법령정보센터에서 검토 시점의 효력을 직접 확인하세요. 적용 여부·적법성·불허 여부를 프로그램이나 LLM이 자동 결정하지 않습니다.

- `STEP 01`에서 합성 신청서 분석 → 담당자 검토 확정.
